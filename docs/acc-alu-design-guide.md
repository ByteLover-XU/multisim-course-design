# 4 位 ACC＋ALU 实物系统设计指南

> **最终控制方式：** `OP2 OP1 OP0` 三位操作码。  
> **当前顶层数据通路：** 外部 B 用于 LOAD，外部 A 与 ACC 进入 ALU。  
> **项目定位：** 本系统是累加器型数据通路，不是完整 CPU。

---

## 一、设计目标

本设计实现一个采用三位操作码控制的 4 位 ACC＋ALU 运算系统。

系统能够完成 CLEAR、LOAD、ADD、SUB、AND、OR 六种基本功能，并通过 ACC 保存结果、参与下一次运算。

系统主要包括：

- 4 位外部 A 输入；
- 4 位外部 B 输入；
- 三位操作码译码；
- 4 位 ALU；
- ACC 累加寄存器；
- B 输入与 ALU_RESULT 选择；
- 手动时钟；
- ACC 四位 LED 显示；
- Carry 显示。

当前顶层未看到独立 Zero 输出，Zero 暂按可选扩展处理。

---

## 二、按当前原理图确定的数据通路

```text
外部 A ───────────────→ ALU A端 ───────────┐
ACC 输出 ─────────────→ ALU B端 ───────────┤
                                              ▼
                                          ALU_RESULT
                                              │
外部 B ───────────────┐                       │
                      ├──→ 74LS157 ───────────┘
ALU_RESULT ───────────┘
                              │
                              ▼
                         74LS175 ACC
                              │
                              ├──→ LED
                              └──→ 反馈到 ALU B端
```

由此可知：

- `LOAD` 时，ACC 装入外部 B；
- 运算时，ACC 装入 ALU_RESULT；
- ALU 的两个主要操作数为外部 A 与 ACC；
- ADD、AND、OR 的结果分别为 `A+ACC`、`A&ACC`、`A|ACC`；
- SUB 的方向必须以 ALU 子模块内部减法器连接为准。

## 三、三位操作码定义

| OP2 | OP1 | OP0 | 功能 | 当前数据通路对应结果 |
|---:|---:|---:|---|---|
| 0 | 0 | 0 | CLEAR | `ACC ← 0000` |
| 0 | 0 | 1 | LOAD | `ACC ← B` |
| 0 | 1 | 0 | ADD | `ACC ← A + ACC` |
| 0 | 1 | 1 | SUB | 由 ALU 内部减法方向决定 |
| 1 | 0 | 0 | AND | `ACC ← A AND ACC` |
| 1 | 0 | 1 | OR | `ACC ← A OR ACC` |
| 1 | 1 | 0 | 保留 | 当前行为未定义 |
| 1 | 1 | 1 | 保留 | 当前行为未定义 |

操作码负责选择功能，时钟按键负责更新 ACC。

### SUB 方向说明

顶层连线只能确认：

```text
ALU A端 = 外部 A
ALU B端 = ACC
```

因此：

- 若 ALU 内部实现 `A-B`，则 SUB 为 `A-ACC`；
- 若 ALU 内部实现 `B-A`，则 SUB 为 `ACC-A`。

在报告和 README 中，不应在未检查 ALU 子模块前直接写成 `ACC-B`。

## 四、译码与有效电平

当前译码模块使用三线—八线译码器：

```text
OP2 OP1 OP0 → 74HC138/同功能器件
```

输出关系：

- `Y0` 直接作为低有效 `CLEAR_N`；
- `Y1` 反相后生成高有效 `LOAD`；
- `Y2` 反相后生成高有效 `ADD_EN`；
- `Y3` 反相后生成高有效 `SUB_EN`；
- `Y4` 反相后生成高有效 `AND_EN`；
- `Y5` 反相后生成高有效 `OR_EN`；
- `Y6`、`Y7` 对应保留操作码。

仿真截图使用 74HC138、74HC04 模型；实际 PCB/BOM 若采用 74LS138、74LS04，应明确区分仿真模型和实物型号。

---

## 五、保留操作码的安全性

`110`、`111` 当前没有定义正式功能。

如果在保留码下仍按下时钟，而 ALU 默认输出不是 ACC 原值，ACC 可能被写入 0、未知值或其他非预期结果。

推荐至少采用一种保护方式：

1. 保留码时屏蔽 ACC 时钟；
2. 保留码时强制选择 ACC 原值，实现 HOLD；
3. 明确规定保留码下禁止按 EXEC，并在报告中说明。

最稳妥的是实现：

```text
OP=110 或 111 时：ACC_next = ACC
```

## 六、状态显示

### Carry

当前顶层具有 Carry 输出。

- ADD 时表示无符号加法进位；
- SUB 时其含义取决于减法器实现；
- 若要显示 Borrow，应核对 Cout 是否需要取反。

### Zero

当前顶层截图未看到独立 Zero 输出。

因此文档应写成：

```text
Zero：可选扩展，当前顶层未实现或待确认。
```

需要补充时，可使用：

```text
Zero = ~(ACC3 | ACC2 | ACC1 | ACC0)
```

## 七、主要器件

| 器件 | 主要作用 |
|---|---|
| 74LS175 | 4 位 ACC 数据保存 |
| 74LS157 | 外部 B 与 ALU_RESULT 选择 |
| 74LS14 | 实物按键消抖与整形 |
| 74LS07 | 缓冲与 LED 驱动 |
| 74LS138 / 同功能译码器 | 三位操作码译码 |
| 74LS04 / 同功能反相器 | 将低有效译码输出转换为高有效使能 |
| 74LS 系列加法器和逻辑门 | ADD、SUB、AND、OR |
| LED、限流电阻 | 数据和状态显示 |
| 拨码开关 | A、B 和 OP2～OP0 输入 |
| 轻触按键 | 手动时钟 |

普通 74HC 与 74LS 不应被描述为可以随意混用。器件替换必须核对输入门限、输出电平和驱动能力。

## 八、推荐测试顺序

### 1. CLEAR

```text
OP=000
预期：ACC=0000
```

### 2. LOAD

```text
B=0011
OP=001
按一次时钟
预期：ACC=0011
```

### 3. ADD

```text
先 LOAD：ACC=0011
A=0010
OP=010
按一次时钟
预期：ACC=0101
```

### 4. AND

```text
先 LOAD：ACC=1010
A=1100
OP=100
预期：ACC=1000
```

### 5. OR

```text
先 LOAD：ACC=1000
A=0011
OP=101
预期：ACC=1011
```

### 6. SUB

SUB 测试前必须先确认 ALU 内部方向。

若内部为 `A-ACC`：

```text
A=0101
ACC=0011
预期：0010
```

若内部为 `ACC-A`：

```text
ACC=0101
A=0011
预期：0010
```

### 7. 保留码

分别测试 `110` 和 `111`：

- 不按时钟时 ACC 应保持；
- 按时钟后的行为必须被明确；
- 最终版本建议实现 HOLD。

---

## 九、PCB 与实物注意事项

- OP0 应接译码器最低位输入，OP2 应接最高位输入；
- 74LS138 使能端必须连接为有效状态；
- `CLEAR_N` 是低有效信号；
- `LOAD`、`ADD_EN`、`SUB_EN`、`AND_EN`、`OR_EN` 为高有效信号；
- 机械按键作为时钟时需要消抖；
- LED 必须串联限流电阻；
- 74LS07 为开集电极输出时需要检查上拉；
- 未使用输入不得悬空；
- 每片芯片电源附近建议配置去耦电容；
- 上电前检查 5V 与 GND 是否短路。
