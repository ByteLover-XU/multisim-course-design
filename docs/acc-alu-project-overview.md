# 基于三位操作码控制的 4 位 ACC＋ALU 项目简介

## 一、项目概述

本项目设计并实现一个采用 `OP2 OP1 OP0` 三位操作码控制的 4 位 ACC＋ALU 运算系统。

系统能够完成 CLEAR、LOAD、ADD、SUB、AND、OR 六种基本功能，并使用 ACC 累加寄存器保存结果。ACC 中的数据可以参与下一次运算，从而实现连续运算。

本项目不是完整 CPU，不包含程序计数器、指令 ROM 和完整取指—译码—执行流程。设计重点是展示组合逻辑、寄存器、操作码译码和时钟控制之间的配合。

---

## 二、当前顶层数据通路

从现有顶层原理图可以确定：

```text
外部 A → ALU A端
ACC    → ALU B端
外部 B → ACC 的 LOAD 输入
ALU_RESULT → ACC 的运算结果输入
```

因此：

- LOAD 装入的是外部 B；
- ADD、AND、OR 使用外部 A 与 ACC 运算；
- SUB 的方向需要以 ALU 子模块内部电路为准。

```text
外部 A ───────→ ALU ───────→ ALU_RESULT ──┐
ACC反馈 ──────→ ALU                         ├──→ ACC → LED
外部 B ────────────────────────────────────┘
```

## 三、三位操作码

| OP2 | OP1 | OP0 | 功能 | 当前电路含义 |
|---:|---:|---:|---|---|
| 0 | 0 | 0 | CLEAR | `ACC ← 0000` |
| 0 | 0 | 1 | LOAD | `ACC ← B` |
| 0 | 1 | 0 | ADD | `ACC ← A + ACC` |
| 0 | 1 | 1 | SUB | 由 ALU 内部减法方向决定 |
| 1 | 0 | 0 | AND | `ACC ← A AND ACC` |
| 1 | 0 | 1 | OR | `ACC ← A OR ACC` |
| 1 | 1 | 0 | 保留 | 当前行为未定义 |
| 1 | 1 | 1 | 保留 | 当前行为未定义 |

操作码决定当前功能，执行按键或时钟边沿负责更新 ACC。

---

## 四、基本工作过程

```text
1. OP=000：清零 ACC；
2. 设置 B，OP=001：将 B 装入 ACC；
3. 设置 A 和运算操作码；
4. 按下时钟；
5. ACC 保存 ALU 结果；
6. 修改 A 或操作码后继续运算。
```

示例：

```text
OP=000：CLEAR          → ACC=0000
B=0011，OP=001：LOAD   → ACC=0011
A=0010，OP=010：ADD    → ACC=0101
A=1100，OP=100：AND    → ACC=0100
```

## 五、译码逻辑

三位操作码由三线—八线译码器处理：

- `000` 产生低有效 `CLEAR_N`；
- `001` 产生 `LOAD`；
- `010` 产生 `ADD_EN`；
- `011` 产生 `SUB_EN`；
- `100` 产生 `AND_EN`；
- `101` 产生 `OR_EN`；
- `110`、`111` 保留。

仿真截图使用 74HC138 和 74HC04 模型。实际 PCB 若采用 74LS138、74LS04，应在 BOM 中写明实际型号。

## 六、当前已实现与待确认内容

### 已实现

- 三位操作码；
- CLEAR；
- LOAD；
- ADD、SUB、AND、OR 使能；
- ACC 结果保存；
- ACC 四位 LED 显示；
- Carry 显示；
- Multisim 仿真；
- PCB 实现。

### 待确认

- SUB 的实际方向是 `A-ACC` 还是 `ACC-A`；
- `110`、`111` 下按时钟是否能安全保持 ACC；
- 当前顶层未看到独立 Zero 输出，Zero 是否实际实现。

## 八、说明

- 本项目是 4 位累加器型运算系统，不是完整 CPU；
- 文档中的 A、B、ACC 含义以顶层原理图实际连线为准；
- 普通 74HC 与 74LS 不应描述为可以随意混用；
- `SUB` 方向必须检查 ALU 子模块后再最终定稿。
